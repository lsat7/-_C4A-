# c4a-evaluator — C4 技能提交自动评审器

## Purpose（解决什么问题）

C4 挑战要求每位同学提交一个可复用、可执行、可验证、IO 明确的技能包，文件发到 WeChat 群。
老师/助教面对一堆文件时，要回答四个问题：**谁交了？交齐了吗？合格吗？怎么改？**

`wechat-doc-mapper` 只解决了第一个问题的一半（扫描→分类），它像"收发室"——能分信，不能阅卷。
本技能把它升级为**自动阅卷系统**：

```
WeChat 群文件夹
      ↓  ① 文件采集与识别（复用 wechat-doc-mapper 的扫描/作者提取）
      ↓  ② 提交完整性检查（C4 五件必交文件）
      ↓  ③ 技能质量评审（C4 四条件，规则引擎 + 可插拔 LLM）
      ↓  ④ 评审报告生成（班级总览 + 排名 + 版本追踪 + 改进建议）
```

## I/O（一句话）

- **输入**：一个本地文件夹路径（WeChat 同步文件夹、手动下载文件夹、任何包含 C4 提交的目录）。
- **输出**：`c4a_eval_report.md`（评审报告）+ `c4a_eval_result.json`（结构化结果）
  +（可选）`c4a_eval_report.xlsx`（Excel 详表）、`c4a_eval_dashboard.html`（班级仪表板）。

> 关键约束：无论文件怎么从 WeChat 获取，技能**只接受一个本地文件夹路径**作为输入——文件怎么来的不影响评审。

## Prerequisites（环境要求）

- **Python 3.8+**（核心仅标准库，**零第三方依赖即可运行**——保证"别人拿过去能直接用"）
- 可选：`pyyaml`（更鲁棒的 YAML 解析；未安装时自动降级为内置解析器）
- 可选：`openpyxl`（生成 Excel 详表；未安装时跳过并提示）
- 若安装了官方 `.skill` 包（ZIP 格式），评审器按二进制处理，不读取内部内容

## Workflow

### Step 1 — 采集与识别（Level 1）

**先确认文件夹路径**（未提供则询问）。然后运行：

```bash
python scripts/c4a_evaluator.py "<文件夹路径>" -o ./c4a_eval_out --format md,json
```

识别逻辑：
- 扫描所有文件，识别文件名含 `_C4_` / `_C4A_` 标记的提交；
- **作者提取回退链**：文件名前缀 → 子目录名 → 文件内首部（作者/Author:）→ `Unknown`（标记待人工确认）；
- 自动识别 `_v2`、`_v3` 版本，槽位认领**最新版本**的文件。

### Step 2 — 完整性检查（Level 2）

对每位作者，检查 C4 五件必交文件是否齐全（**贪心一对一分配 + 特异性优先**，避免误配）：

| 必交文件 | 检测方式 |
| --- | --- |
| Skill 说明文档 | 文件名含 `skill说明` / `skill_doc`，或 .md 内容含"输入/输出/使用场景" |
| 可执行内容 | `.skill` / `.py` / 含 YAML frontmatter 的 .md / 有代码块 |
| Demo | `.mp4` / `.mov` / `.png` / `.jpg` / `.gif` / 文件名含 `demo` |
| 教学说明 | 文件名含 `教学` / `tutorial`，或内容含"上手/步骤/常见坑" |
| AI 日志 | 文件名含 `AI日志` / `AI_log`，或内容含"使用的 AI 工具/prompt/迭代" |

输出：`✅ 齐全(5/5)` / `⚠️ 部分缺失(3–4)` / `❌ 严重缺失(<3)` + 具体缺什么。

### Step 3 — 质量评审（Level 3）

对每个提交按 **C4 四条件**自动评分。**评分口径全部定义在 `references/rubric.yaml`**（单一事实来源，代码零硬编码阈值）：

| 条件 | 规则要点（详见 rubric.yaml） |
| --- | --- |
| **可复用** | 有安装说明？无绝对路径/密钥（负向信号）？有环境要求？有泛化说明？ |
| **可执行** | 有可运行代码/.skill 包？包结构完整？无 Python 语法错误（静态检查）？有 IO 契约？ |
| **可验证** | 有测试/示例？有预期结果？有可复现运行证据？ |
| **IO 明确** | 有"输入…输出…"一句话（正则）？输入类型明确？输出类型明确？ |

评级：`✅ 达标(raw≥0.667)` / `⚠️ 部分(≥0.333)` / `❌ 缺失`。**每条判定输出证据**（命中词/命中文件/未命中项），不是只给分。

> **技术选型**：默认 **纯规则引擎**（确定性、离线、零成本、可复现）。LLM 深审为**可插拔层**
> （`LLMReviewer` 接口），在需要语义级判断时注入。选型理由见方案设计文档。

### Step 4 — 报告生成（Level 4）

生成完整班级评审报告：

```bash
# 全格式
python scripts/c4a_evaluator.py "<文件夹>" -o ./out --format md,json,excel,html
```

报告含：
1. **班级总览仪表板**：提交人数、完整率、质量分布、最常缺失文件、四条件通过率
2. **综合排名**：`综合分 = 完整性 × 0.4 + 质量分(归一) × 0.6`（权重可配置）
3. **版本追踪**：识别 `_v2`/`_v3`，展示进步轨迹
4. **作者详情**：完整性矩阵 + 四条件评级 + **逐规则证据**（可展开）+ 个性化改进建议
5. **全班改进建议**：最常见缺失、最弱维度、下次提交自检清单

### Step 5 — 自检与迭代

修改 `references/rubric.yaml` 后**无需改代码**即可调整口径。改动后务必运行自测：

```bash
python scripts/self_test.py
```

自测套件含 59 项断言（规则加载 / 作者识别 / 完整性 / 质量规则 / 边界 / 回归 / 端到端），并输出精确率/召回率。

## Edge Cases（边界情况）

| 情况 | 处理 |
| --- | --- |
| 空文件夹 | 报告"未找到 C4 相关文件"，列出扫描路径与匹配规则，不崩溃 |
| 文件名不规范 | 回退到子目录/内容识别，标记 `low_confidence` 供人工确认 |
| 超大文件（>50MB） | 跳过内容分析，仅做文件名/类型匹配 |
| 二进制文件（.mp4/.skill） | 仅做文件名/扩展名匹配，不读取内容 |
| 非 C4 文件混入 | 过滤后在报告末尾单独列出 |
| 同一作者多版本 | 识别 `_v2`/`_v3`，槽位认领最新版本，报告迭代轨迹 |
| 中文编码（GBK/UTF-8） | UTF-8 → GBK → GB18030 → latin-1 依次回退 |
| Python 语法错误 | `ast.parse` 静态检查，命中负向信号扣分 |
| 无 pyyaml / openpyxl | 自动降级（内置 YAML 解析器 / 跳过 Excel），核心功能不受影响 |

## 校准（校准集）

`tests/fixtures/` 内含 5 组构造的对抗性夹具，覆盖：完整提交、部分缺失、严重缺失、
多版本迭代、语法错误、GBK 编码、通用目录名。运行自测可复现全部判定。

## 可移植性

- 只依赖一个文件夹路径输入，跨平台（Windows / macOS / Linux）可用；
- 所有阈值/权重/信号集中在 `references/rubric.yaml`，换课程/换挑战只改这一个文件；
- 核心零第三方依赖，老师/助教 clone 下来即可运行。
